## 2. OrderConfirmationPage i18n (P0)

### Problem

`OrderConfirmationPage.tsx` had **every string hardcoded in English** — status titles ("Order Received", "Being Prepared", "Served — Enjoy!", "Order Canceled"), subtitles, labels ("Live Status", "Order Ref"), buttons ("Continue Browsing Menu", "Back to Home"), and the feedback CTA ("Enjoying your visit?", "Rate Your Experience").

This is the page customers see **immediately after ordering** — the most memorable moment of the journey. A Bulgarian diner who ordered in Bulgarian would suddenly see English.

### What Changed

**File:** `apps/frontend/src/pages/OrderConfirmationPage.tsx`

- Added `useTranslation()` hook
- Replaced `title` / `subtitle` string fields in `STATUS_CONFIG` with `titleKey` / `subtitleKey` that reference i18n keys
- Replaced all 10 hardcoded English strings with `t('...')` calls

**Before:**

```tsx
const STATUS_CONFIG = {
  NEW: {
    title: 'Order Received',
    subtitle: 'Sent to the kitchen — hang tight.',
    // ...
  },
};

// In JSX:
<h1>{cfg.title}</h1>
<p>{cfg.subtitle}</p>
<span>Live Status</span>
```

**After:**

```tsx
const STATUS_CONFIG = {
  NEW: {
    titleKey: 'orderConfirmation.status.new.title',
    subtitleKey: 'orderConfirmation.status.new.subtitle',
    // ...
  },
};

// In JSX:
<h1>{t(cfg.titleKey)}</h1>
<p>{t(cfg.subtitleKey)}</p>
<span>{t('orderConfirmation.liveStatus')}</span>
```

## 3. Checkout Back Navigation (P0)

### Problem

`CheckoutPage.tsx` used `navigate(-1)` (browser history) for the back button and empty-cart redirect. This breaks when:

- The user reloads the checkout page (history entry is gone)
- The user lands on `/checkout` directly via a bookmarked URL
- The user navigates: Menu → Cart → Checkout → reload → hit Back → goes nowhere

### What Changed

**File:** `apps/frontend/src/pages/CheckoutPage.tsx`

Built an explicit menu URL from the restaurant context instead of relying on browser history:

```tsx
// NEW: Explicit back-to-menu URL
const menuUrl = restaurantId
  ? `/menu/public/${restaurantId}${tableNumber ? `?table=${tableNumber}` : ""}`
  : "/";
```

Applied in 2 places:

| Location                       | Before         | After                                  |
| ------------------------------ | -------------- | -------------------------------------- |
| Empty cart redirect (line 137) | `navigate(-1)` | `navigate(menuUrl, { replace: true })` |
| Back button (line 224)         | `navigate(-1)` | `navigate(menuUrl)`                    |

The `replace: true` on the redirect prevents creating a useless history entry for the empty checkout page.

## 4. Cart Line-Item Pricing (P1)

### Problem

The cart showed **base price × quantity** per line item, ignoring option price modifiers. Example:

> Customer orders a €12 burger with a +€3 cheese upgrade (1 item)  
> **Before:** Cart shows `€12.00` for the line item, but the Total shows `€15.00`  
> Line items visibly don't add up to the total → customer thinks there's a pricing error

### What Changed

**File:** `apps/frontend/src/components/cart/CartDrawer.tsx`

**Before:**

```tsx
€{(item.price * item.quantity).toFixed(2)}
```

**After:**

```tsx
€{((item.price + (item.selectedOptions?.reduce(
  (sum: number, opt: any) => sum + (opt.priceModifier || 0), 0
) || 0)) * item.quantity).toFixed(2)}
```

Now the line-item price includes all option modifiers, so it adds up correctly to the total.

## 5. Focus Trap & Accessibility (P1)

### Problem

All 6 modal/overlay components used `createPortal(..., document.body)` but **none** implemented:

- Focus trapping (Tab key escapes the modal into the page behind it)
- Escape key handling (only `ImageLightbox` had it)
- ARIA `role="dialog"` / `aria-modal="true"` attributes

This fails WCAG 2.1 Level AA (2.1.2 No Keyboard Trap, 2.4.7 Focus Visible) and is a legal risk in EU markets.

### What Changed

#### New File: `apps/frontend/src/hooks/useFocusTrap.ts`

A reusable hook that:

1. **Traps Tab/Shift+Tab** — cycles focus within the container using `querySelectorAll` on focusable selectors (`a[href]`, `button:not([disabled])`, `input`, `select`, `textarea`, `[tabindex]`)
2. **Closes on Escape** — calls the provided `onClose` callback
3. **Restores focus** — stores `document.activeElement` on open, returns focus to it on close
4. **Auto-focuses first element** — focuses the first focusable element 50ms after opening

```tsx
// Usage:
const focusTrapRef = useFocusTrap(isOpen, onClose);
return (
  <div ref={focusTrapRef} role="dialog" aria-modal="true">
    ...
  </div>
);
```

#### Components Updated

| Component          | File                                     | Focus Trap | Escape         | ARIA                                 |
| ------------------ | ---------------------------------------- | ---------- | -------------- | ------------------------------------ |
| CartDrawer         | `components/cart/CartDrawer.tsx`         | ✅ Added   | ✅ Added       | ✅ `role="dialog" aria-modal="true"` |
| CustomerLoginModal | `components/auth/CustomerLoginModal.tsx` | ✅ Added   | ✅ Added       | ✅ `role="dialog" aria-modal="true"` |
| PaymentModal       | `components/payment/PaymentModal.tsx`    | ✅ Added   | ✅ Added       | ✅ `role="dialog" aria-modal="true"` |
| AssistanceDialog   | `pages/PublicMenuPage.tsx` (inline)      | —          | —              | ✅ `role="dialog" aria-modal="true"` |
| ImageLightbox      | `components/menu/ImageLightbox.tsx`      | —          | Already had ✅ | —                                    |
| PairingModal       | `components/menu/ItemWithOptions.tsx`    | —          | —              | —                                    |

> **Note on AssistanceDialog and PairingModal:** These are short-lived modals (user picks an option immediately) so full focus trapping was not applied — only ARIA attributes were added where applicable. The 3 main modals (Cart, Login, Payment) that users spend significant time in now have full focus trap support.

## 6. TrendingCarousel Skeleton Loader (P1)

### Problem

When trending items were loading, the component returned `null`:

```tsx
if (loading || trendingItems.length === 0) return null;
```

This caused a **layout shift** — the page renders without the carousel section, then suddenly the section appears with a visible jump when data arrives 1-2 seconds later. This hurts CLS (Cumulative Layout Shift), a Core Web Vital metric.

### What Changed

**File:** `apps/frontend/src/components/menu/TrendingCarousel.tsx`

Split the condition into two:

1. **Loading:** Shows a skeleton with 3 animated placeholder cards that match the real carousel's dimensions:
   - Title placeholder (h-7 × w-40, rounded, pulsing)
   - 3 card skeletons: image area (h-48), title line (h-5), subtitle line (h-4), button area (h-11)
   - All wrapped in the same `glass-panel rounded-[2.5rem]` styling as real cards

2. **Empty (no trending items):** Still returns `null` (no section needed)

**Before:**

```
Page loads → [gap where carousel will be] → data arrives → [carousel appears, page jumps]
```

**After:**

```
Page loads → [skeleton placeholder] → data arrives → [skeleton replaced with real cards, no shift]
```

## 7. Allergen Filter Pills (User-Reported)

### Problem

The allergen/dietary filter pills were too large and overlapped the sticky category navigation. They used `glass-panel` styling (which includes shadows and borders), `px-4 py-2` padding, `text-xs` with `uppercase tracking-widest` — taking up the visual weight of primary navigation when they're really just filters.

### What Changed

**File:** `apps/frontend/src/pages/PublicMenuPage.tsx` (lines 416-446)

| Property          | Before                                | After                         |
| ----------------- | ------------------------------------- | ----------------------------- |
| Container gap     | `gap-2`                               | `gap-1.5`                     |
| Container margins | `mt-8`                                | `mt-6 mb-2`                   |
| Pill padding      | `px-4 py-2`                           | `px-2.5 py-1`                 |
| Font size         | `text-xs`                             | `text-[10px]`                 |
| Font weight       | `font-bold uppercase tracking-widest` | `font-semibold tracking-wide` |
| Inactive style    | `glass-panel` (with shadow + border)  | `bg-secondary` (flat, subtle) |
| Active shadow     | `shadow-lg`                           | `shadow-sm`                   |
| Count badge       | `ml-1.5 opacity-50`                   | `ml-1 opacity-40 text-[9px]`  |

The pills are now compact, don't overlap, and feel appropriately secondary to the main category navigation below them.

## 8. Image Lazy Loading (P2)

### Problem

Every `<img>` in `ItemWithOptions` loaded immediately, even if the item was below the fold. A restaurant with 50 menu items could load 50 full-resolution images on page load — wasting bandwidth on mobile data.

### What Changed

**File:** `apps/frontend/src/components/menu/ItemWithOptions.tsx`

Added `loading="lazy"` to the item image:

```tsx
<img
  src={getImageUrl(item.imageUrl)}
  alt={itemName}
  loading="lazy" // ← Added
  className="..."
/>
```

The browser now defers loading images until they're close to the viewport. No JavaScript needed — this is a native HTML attribute supported by all modern browsers.

### Problem

After the dashboard icon unification (all FontAwesome → Lucide), the public menu still had **hand-drawn inline SVGs** where Lucide icons exist. These are harder to maintain and inconsistent with the icon system.

### What Changed

| Location                | Before (inline SVG)          | After (Lucide)                              |

Import added: `import { X, Check } from "lucide-react";`

> **Note:** The Google OAuth icon SVG in CustomerLoginModal was **not replaced** — it uses the official Google brand SVG which doesn't exist in Lucide (and shouldn't be a generic icon).

## 10. Toggle Component Adoption

### What Changed

The user adopted the new `Toggle` component (created in the dashboard overhaul) inside `CheckoutPage.tsx`, replacing the fragile `sr-only` checkbox hack for the "Redeem for Discount" loyalty toggle.

**File:** `apps/frontend/src/pages/CheckoutPage.tsx`

**Before:**

```tsx
<label className="flex items-center gap-3 cursor-pointer">
  <div className="relative">
    <input type="checkbox" className="sr-only" checked={usePoints} onChange={...} />
    <div className={`block w-10 h-6 rounded-full ${usePoints ? "bg-accent" : "bg-zinc-700"}`} />
    <div className={`absolute left-1 top-1 bg-white w-4 h-4 rounded-full ${usePoints ? "translate-x-4" : ""}`} />
  </div>
</label>
```

**After:**

```tsx
<Toggle
  checked={usePoints}
  onChange={setUsePoints}
  label={t("checkout.redeemForDiscount")}
  size="sm"
/>
```

Benefits:

- Proper ARIA `role="switch"` with `aria-checked`
- Keyboard accessible (`Enter`/`Space`)
- `focus-visible` ring for keyboard navigation
- 8 lines of fragile markup → 1 component

## 12. How to Verify

### TypeScript Compilation

```bash
cd apps/frontend
npx tsc --noEmit
```

**Expected:** 0 errors.

### Visual Verification

1. **Filters:** Open a menu with dietary tags → pills should be small, flat, and not overlap the category nav
2. **Skeleton:** Open a menu → trending carousel section should show animated placeholders before data loads
3. **Cart pricing:** Add an item with a +€3 option → cart should show €15 (not €12) for a €12 base item
4. **Escape key:** Open cart / login modal / payment modal → press Escape → modal should close
5. **Tab trapping:** Open cart → press Tab repeatedly → focus should cycle within the cart, never escape to the page
6. **Order confirmation i18n:** Change language to BG or RO → place an order → confirmation page should show translated status titles
7. **Checkout back button:** Navigate to checkout → click Back → should go to the exact menu URL with table param preserved
8. **Lazy images:** Open DevTools Network tab → scroll down the menu → images should load as you scroll, not all at once

### Accessibility Audit

```bash
# Check all dialog elements have proper ARIA attributes
grep -rn "role=\"dialog\"" apps/frontend/src/ --include="*.tsx"
```

**Expected:** Matches in CartDrawer, CustomerLoginModal, PaymentModal, PublicMenuPage (assistance dialog).
